# Contract: `ink` Block Format, v1

This is the public, stored contract. Once v1 is released it is frozen: later plugin versions MUST
keep decoding it (constitution II, FR-028). Any change to the grammar or payload layout requires a
new version number.

## Markdown form

````md
```ink
v1;id=k3f9x2ab;700x260;<base64 payload>
```
````

An empty drawing is literally `v1;id=k3f9x2ab;700x260;` (empty payload). Real, byte-exact examples
are the golden fixtures below, generated by the first implementation.

- Fence: an opening fence of ≥ 3 backticks or tildes with the info string exactly `ink`; a closing
  fence of the same character with at least the same length (CommonMark).
- The block contains exactly one content line (the block line). Blank lines around it are tolerated
  on read and never produced.
- The fence and block line may share a common prefix of spaces and/or blockquote markers (e.g. inside
  a callout: `> ```ink`). The prefix is preserved byte-for-byte on update.
- Line endings (`\n` or `\r\n`) are preserved on update.

## Block line grammar

```abnf
block-line = version ";" "id=" id ";" size ";" payload
version    = "v" 1*DIGIT                 ; "v1" for this contract
id         = 8( %x30-39 / %x61-7A )      ; [0-9a-z]{8}
size       = width "x" height            ; decimal integers, each 64..4096
payload    = *( ALPHA / DIGIT / "+" / "/" ) *2"="   ; RFC 4648 base64, may be empty
```

Trailing whitespace after the payload is ignored on read and not written.

## Payload (after base64 decode and raw-DEFLATE inflate)

All integers are LEB128 varints. Signed values use zigzag encoding (`(n << 1) ^ (n >> 31)`).

```text
uvarint  strokeCount
repeat strokeCount:
  uvarint  pointCount            ; ≥ 1
  svarint  x0                    ; absolute, canvas units
  svarint  y0
  uvarint  p0                    ; 0..255
  repeat pointCount - 1:
    svarint dx                   ; delta from previous point
    svarint dy
    svarint dp
```

- An empty drawing has an empty payload string (no DEFLATE stream at all).
- Decoders MUST reject: trailing bytes after the last stroke, truncated varints, `pointCount = 0`,
  pressure outside 0..255, and coordinates outside `[0, width] × [0, height]`.
- Encoders MUST be deterministic: the same drawing always produces the same line
  (DEFLATE level 9, no timestamps or random data in the payload).

## Error handling

| Condition | Result | Rendering | Rewritten automatically? |
|-----------|--------|-----------|--------------------------|
| Header doesn't match grammar | `malformed` | "Can't read this drawing" placeholder | Never |
| `v2`+ (unknown version) | `unsupported-version` | "Made with a newer version of the plugin" placeholder | Never |
| Payload fails to decode | `malformed` | Same as malformed | Never |
| More than one content line | `malformed` | Same as malformed | Never |

## Golden fixtures

`tests/fixtures/v1/*.md` hold real blocks with the expected decoded drawing as JSON next to them
(`*.json`). Fixture tests assert both `decode(line) == expected` and `encode(expected) == line`.
Fixtures are append-only; they are never edited or deleted.
